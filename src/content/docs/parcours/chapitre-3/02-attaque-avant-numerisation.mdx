## De la grandeur physique à la décision

Dans le TP1, votre contrôleur lit un capteur DHT22, compare la température à des seuils, puis allume une LED et déclenche un buzzer. Cette chaîne est celle de tous les systèmes embarqués.

<ChaineMesure />

Toute la sécurité « classique » (chiffrement, authentification, signatures) agit à droite de la frontière : sur des données déjà numérisées. Une attaque sur le capteur agit **à gauche**, sur la grandeur physique elle-même.

:::caution[Une mesure authentique d'un phénomène falsifié]
Le capteur fonctionne, le convertisseur fonctionne, le logiciel est exempt de bogue : la mesure est pourtant fausse, parce que le phénomène a été falsifié avant d'être mesuré. Le logiciel l'accepte comme vraie.
:::

## Usurpation ou brouillage ?

Il existe deux grandes façons de perturber un capteur.

| | Usurpation (*spoofing*) | Brouillage (*jamming*) |
|---|---|---|
| **Principe** | Le capteur reçoit un signal falsifié, crédible. | Le capteur est noyé dans le bruit. |
| **Ce que délivre le capteur** | Une valeur **fausse mais plausible**. | Aucune mesure exploitable. |
| **Visibilité** | Rien n'indique une panne : le système décide sur de fausses informations. | La défaillance est visible : un mode dégradé est possible. |

Dans la grille STRIDE de la [page précédente](/Embedded-System-Course/parcours/chapitre-3/01-menaces-et-stride/), une usurpation relève de *Spoofing* ou de *Tampering* (la mesure fournie est falsifiée), et le brouillage de *Denial of service* (la mesure n'est plus disponible).
