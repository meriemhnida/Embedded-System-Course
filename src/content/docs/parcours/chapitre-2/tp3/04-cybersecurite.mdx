## La console de maintenance

Le technicien règle le nœud depuis le moniteur série. La console distingue les commandes **publiques** et les commandes **réservées** à une session authentifiée.

| Commande | Accès | Effet |
|---|---|---|
| `AIDE` | public | Liste des commandes autorisées |
| `ETAT` | public | État, mesures, seuil, session, boîtier |
| `STATS` | public | Indicateurs d'exploitation (partie D) |
| `CONNEXION <pin>` | public | Ouvre une session |
| `DECONNEXION` | session | Ferme la session |
| `PIN <ancien> <nouveau>` | session | Change le code PIN |
| `SEUIL <valeur>` | session, PIN d'usine changé | Modifie le seuil d'alarme |
| `JOURNAL` | session, PIN d'usine changé | Affiche le journal d'audit |
| `ACQUITTER` | session, PIN d'usine changé | Met fin à une intrusion, acquitte une alarme |
| `TEST …` | session, PIN d'usine changé, mode test | Injection de fautes |

:::note[Information]
Sans session, une commande réservée reçoit **la même réponse** qu'une commande inconnue : on ne renseigne pas un attaquant sur ce qui existe. De même, `AIDE` n'affiche les commandes réservées qu'une fois la session ouverte.
:::

## C1. Valider les entrées (SEC-2)

Toute donnée qui entre dans le système est **suspecte** tant qu'elle n'a pas été validée. La fonction `lireConsole()`, fournie, lit les caractères **sans attendre** dans un tampon de taille fixe :

```cpp
} else if (c < 0x20 || c > 0x7E) {
  ligneRejetee = true;   // caractère de contrôle ou non ASCII
} else if (lgLigne < LIGNE_MAX) {
  ligne[lgLigne++] = c;
} else {
  ligneRejetee = true;   // jamais d'écriture au-delà du tampon
}
```

## C2. Authentifier et freiner les attaques par force brute (SEC-1)

La comparaison du PIN est fournie. Elle s'exécute en **temps constant** : sa durée ne dépend pas de la position du premier chiffre faux.

```cpp
bool pinEgal(const char *saisi, const char *attendu) {
  if (strlen(saisi) > 6) return false;
  char tampon[7];
  memset(tampon, 0, sizeof(tampon));
  strncpy(tampon, saisi, 6);
  uint8_t difference = 0;
  for (uint8_t i = 0; i < 7; i++) difference |= (uint8_t)(tampon[i] ^ attendu[i]);
  return difference == 0;
}
```

Complétez `connexion()` (`TODO C2`) : aucune tentative n'est évaluée pendant un verrouillage ; chaque échec incrémente `config.echecs`, **enregistré en EEPROM** ; à partir du 3<sup>e</sup> échec, le nœud se verrouille 30 s, puis 1 min, 2 min, 4 min et 8 min au plus. Dans `setup()`, reprenez le verrouillage si `config.echecs` atteint déjà 3.

## C3. Supprimer le mot de passe universel (SEC-3)

Tous les boîtiers sortent d'usine avec le PIN `0000`. Écrivez `changerPin()` et le contrôle de `traiterCommande()` (`TODO C3`) : tant que `config.pinUsine` vaut 1, toute commande autre que `PIN` et `DECONNEXION` est refusée. Le nouveau PIN comporte 4 à 6 chiffres ; refusez les suites triviales (1111, 1234, 4321…) et l'ancien PIN. Un ancien PIN faux compte comme un échec d'authentification et ferme la session.

## C4. Garantir l'intégrité de la configuration (SEC-4)

La configuration est une structure enregistrée en EEPROM :

```cpp
struct Config {
  uint16_t magic;       // signature 0x5345 : « cette zone contient bien notre configuration »
  uint8_t version;      // format de la structure
  float seuilAlarme;    // °C
  char pin[7];          // 4 à 6 chiffres, complété par des '\0'
  uint8_t pinUsine;     // 1 tant que le PIN d'usine n'a pas été changé
  uint8_t echecs;       // échecs d'authentification consécutifs
  uint8_t crc;          // CRC-8 de tous les octets qui précèdent
};
```

`sauverConfig()` calcule le CRC puis écrit la structure avec `EEPROM.put()`, qui ne réécrit que les octets modifiés pour limiter l'usure. Complétez `chargerConfig()` (`TODO C4`) : vérifiez la signature, la version, le CRC, les bornes du seuil et la fin du PIN. Si un contrôle échoue, journalisez `EVT_CONFIG_USINE` (EEPROM vierge) ou `EVT_CONFIG_CORROMPUE`, puis repartez des valeurs par défaut.

Pour tester, ouvrez une session, changez le PIN, puis tapez `TEST CORROMPRE` et `TEST BLOCAGE`. Le chien de garde redémarre la carte **sans effacer l'EEPROM** ; au démarrage, vous devez lire `# EVT CONFIG_CORROMPUE`. Relancer la simulation depuis Wokwi peut au contraire repartir d'une EEPROM vierge.

## C5. Détecter l'ouverture du boîtier (SEC-5)

Le contact d'ouverture relie D4 à la masse quand le boîtier est **fermé**. Écrivez `surveillerBoitier()` (`TODO C5`) en filtrant les rebonds sur 50 ms. ## C6. Le journal d'audit (SEC-6)

Le journal, fourni, conserve les **16 derniers événements** dans un tampon circulaire. Quand il est plein, l'événement le plus ancien est écrasé et le compteur `journalPerdus` augmente. La commande `JOURNAL` l'affiche.

## Critères de validation

- [ ] Aucune commande de configuration n'est possible sans session ni avant le changement du PIN d'usine.
- [ ] Trois PIN faux verrouillent la console, même après un redémarrage par `TEST BLOCAGE`.
- [ ] Toutes les entrées de QC.3 sont traitées comme attendu, sans plantage.
- [ ] Une configuration corrompue est détectée au démarrage et remplacée par des valeurs sûres.
- [ ] L'ouverture du boîtier déclenche INTRUSION ; seul `ACQUITTER`, en session et boîtier fermé, y met fin.
- [ ] Le journal ne contient aucun PIN.
